LLM Training Lifecycle

An interactive notebook: how a Large Language Model goes from raw text to a helpful assistant.

[1] Markdown · Introduction

Two buckets, one model

Training an LLM is split into two big phases. Pre-training builds the model's "brain" from scratch by reading huge amounts of text. Post-training takes that brain and teaches it to behave like a helpful, safe, conversational assistant.

Mental model: Pre-training teaches the model what language is and what the world contains. Post-training teaches it how to use that knowledge when talking to a person.

[1] Markdown · Phase 1 overview

Pre-Training: building the foundation

Pre-training reads massive web archives to learn grammar, facts, reasoning, and language patterns. It has two stages: Base Pre-Training (general knowledge) and Continual Pre-Training (specialist knowledge).

[2] Stage 1.1 · Base Pre-Training unsupervised

Base Pre-Training

Goal: teach language structure, world knowledge, and next-token prediction.
Data: trillions of tokens of raw internet text (Wikipedia, books, news, open-source code).
Mechanism: feed a continuous stream of text and train the model to predict the very next token.

Output · the training loop
# the whole idea in one line loss = -log P(next_token | all previous tokens) # cross-entropy, averaged over the corpus

[3] Stage 1.2 · Continual Pre-Training (CPT) domain adaptation

Continual Pre-Training / Domain Adaptation

When: right after base pre-training. It takes the base model as its starting point.
Goal: expand the base model's knowledge into a niche it has not seen enough of (legal, medical journals, Linux manuals, a codebase).
Data: unstructured, raw domain documents.
Mechanism: keep training with the same next-token objective, so the weights absorb specialist vocabulary and syntax.

[4] Markdown · Summary
  • Base pre-training = general knowledge, unlabeled text, next-token loss.
  • CPT = step 2, run after base pre-training on a domain corpus with the same objective, usually mixed with general data to avoid forgetting.
  • Output is a base model: fluent, knowledgeable, but it only continues text. It does not yet know it should answer you.
[1] Markdown · Phase 2 overview

Post-Training: from text continuer to assistant

Post-training starts from a model that already knows how language works. It teaches the model to follow instructions (SFT) and to prefer answers humans like (preference alignment).

[2] Stage 2.1 · Supervised Fine-Tuning (SFT) instruction tuning

Supervised Fine-Tuning / Instruction Tuning

Goal: follow instructions, format answers, and act like an assistant instead of continuing blocks of text.
Data: curated prompt-and-response pairs.
Mechanism: fine-tune (often with LoRA or QLoRA, which update a small set of extra weights) to map user intents to accurate, structured answers.

[3] Stage 2.2 · Preference Alignment (DPO / RLHF) human preferences

Preference Alignment

Goal: align behavior with human values: helpful, safe, honest, polite, and free of toxic or hallucinated output.
Data: human rankings of two answers to the same prompt, or scores from an automated reward model.
Mechanism: reinforce what people prefer and penalize harmful, biased, or unhelpful responses.

Quiz: which answer would you reward?

Prompt: "How do I get rid of a cough?"

[4] Markdown · Summary
  • SFT teaches the format and intent of being an assistant, using example pairs.
  • Preference alignment teaches which good answers humans prefer, using comparisons.
  • Together they turn the base model into the assistant you chat with.
