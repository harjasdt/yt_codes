⚡ Working with LLMs
A practical guide

Stop just chatting with LLMs.
Start building with them.

Anyone can type into a chatbot. The people who pull ahead are the ones who know how to plug a model into their own code, data and workflows.

Jobs are shifting around LLMs

New titles keep appearing and old ones are being redefined, but they share one core skill: knowing how to work with an LLM.

GenAI Engineer

Builds products on top of foundation models: prompts, APIs, RAG, evaluation.

AI Engineer

Software engineer who integrates models into real applications and ships them.

Agentic AI Engineer

Designs agents that use tools and take multi-step actions reliably and safely.

Data Scientist / Analyst

Uses LLMs to extract, classify and analyse text data, and to speed up analysis work.

ML Engineer

Moves from training everything to fine-tuning, serving and running models locally or in the cloud.

Software Developer

Same job, new toolbox: LLM calls become a normal part of the stack.

The common thread: prompts, APIs, local vs cloud models, and tool calling are the basics under every one of these roles. Learn the core once, and you can move between them.

Part 1 · Local

Run LLMs on your own machine with Ollama

Ollama downloads open-weight models and serves them through a CLI and a local REST API. Nothing leaves your laptop.

Why local? Free, private, works offline, and no rate limits. The trade-off: the model you can run is limited by your RAM / GPU.
1

Install Ollama

Download the installer from ollama.com/download (macOS, Windows, Linux). On Mac with Homebrew you can also do:

bash
brew install ollama
ollama --version

The desktop app starts the server for you. If you installed only the CLI, start it yourself with ollama serve.

2

Run your first model

ollama run downloads the model the first time, then opens an interactive chat. Browse available models at ollama.com/library.

bash
ollama run llama3.1:8B
# type a prompt, then /bye to exit
Pick a size that fits your RAM. Rule of thumb: 1B–3B models run comfortably on 8 GB; 7B–8B models want about 16 GB. Smaller models are faster but weaker.
3

Learn the core commands

bash
ollama pull qwen3        # download a model without chatting
ollama list              # models on disk
ollama ps                # models currently loaded in memory
ollama show llama3.1:8B     # details: parameters, context length, template
ollama stop llama3.1:8B     # unload from memory
ollama rm llama3.1:8B       # delete from disk
4

It's also a REST API

Ollama listens on localhost:11434. This is what every library talks to under the hood.

bash
curl http://localhost:11434/api/generate -d '{
  "model": "llama3.1:8B",
  "prompt": "Explain what an LLM is in one sentence.",
  "stream": false
}'
5

Use it from Python

bash
pip install ollama
python · chat.py
import ollama

response = ollama.chat(
    model="llama3.1:8B",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user",   "content": "Why is the sky blue?"},
    ],
)
print(response.message.content)

# Streaming: tokens appear as they're generated
for chunk in ollama.chat(
    model="llama3.1:8B",
    messages=[{"role": "user", "content": "Write a haiku about Python."}],
    stream=True,
):
    print(chunk.message.content, end="", flush=True)
6

Bonus: it speaks the OpenAI API format

Many tools expect an OpenAI-style endpoint. Point them at Ollama and they just work, so you can swap between local and cloud by changing two lines.

python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")  # key is ignored
r = client.chat.completions.create(
    model="llama3.1:8B",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(r.choices[0].message.content)

Part 2 · Cloud API

Call hosted models with the Gemini API

Google AI Studio gives you an API key and a free tier for Gemini models. Everything below follows the official Gemini API docs.

Why cloud? The strongest models, no hardware needed, huge context windows and multimodal input (images, audio, video, PDFs). The trade-off: your data is sent to a provider and heavy use costs money.
Note. Model names, free-tier limits and data-usage terms change often. Check the models, rate limits and pricing pages for the current numbers, and swap the model name in the code below (written with gemini-3.5-flash) if a newer Flash model is listed.
1

Get a free API key

Sign in with a Google account at aistudio.google.com/apikey and click Create API key. Treat it like a password: never commit it or show it on screen.

bash
# the SDK reads GEMINI_API_KEY automatically
export GEMINI_API_KEY="your-key-here"
2

Install the official SDK

bash
pip install google-genai

Note the package is google-genai (the current SDK), not the older google-generativeai.

3

First request

python · gemini_basic.py
from google import genai

client = genai.Client()  # picks up GEMINI_API_KEY

response = client.models.generate_content(
    model="gemini-3.5-flash",
    contents="Explain how AI works in a few words",
)
print(response.text)

Same call over plain REST, which is useful for showing there's no magic:

bash
curl "https://generativelanguage.googleapis.com/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H "Content-Type: application/json" \
  -X POST \
  -d '{"contents":[{"parts":[{"text":"Explain how AI works in a few words"}]}]}'
4

System instructions & settings

Control behaviour with a system instruction and generation config such as temperature.

python
from google import genai
from google.genai import types

client = genai.Client()

response = client.models.generate_content(
    model="gemini-3.5-flash",
    contents="What is a vector database?",
    config=types.GenerateContentConfig(
        system_instruction="You are a friendly teacher. Answer in 3 sentences.",
        temperature=0.3,
    ),
)
print(response.text)
5

Streaming

python
stream = client.models.generate_content_stream(
    model="gemini-3.5-flash",
    contents="Write a short story about a robot learning to cook.",
)
for chunk in stream:
    print(chunk.text, end="", flush=True)
6

Multi-turn chat

The chat helper keeps the conversation history for you.

python
chat = client.chats.create(model="gemini-3.5-flash")

print(chat.send_message("My name is Sam and I love cricket.").text)
print(chat.send_message("What's my name and what do I like?").text)
7

Structured JSON output

Ask the model to return data that matches a schema, so your code can use it directly.

python
from pydantic import BaseModel

class Recipe(BaseModel):
    name: str
    ingredients: list[str]
    minutes: int

response = client.models.generate_content(
    model="gemini-3.5-flash",
    contents="Give me a simple pancake recipe.",
    config={
        "response_mime_type": "application/json",
        "response_schema": Recipe,
    },
)
print(response.parsed)  # a Recipe object

Cloud best practices

🔐 Protect your key

Use environment variables or a .env file in .gitignore. Never paste a key into a public repo or frontend.

⏱ Expect limits

Free tier has rate limits. Add retries with backoff and handle 429 errors gracefully.

🔒 Mind the data

Check the terms for your tier before sending anything private or confidential. This is where local models shine.

Part 3 · Agents

Give an LLM tools with LangChain

A chat model can only produce text. An agent can decide to call your functions, read the results, and keep going until the job is done.

From LLMs to agents

Why a plain model isn't enough, what tools are, and why agents are showing up now.

💬

An LLM only talks

A model takes text in and gives text out. Its knowledge stops at its training date, it can't look anything up, it can be shaky at exact maths, and it can't do anything in the real world.

🔧

Tools fix that

A tool is just a function you write (check weather, search the web, query a database, send an email) plus a description. The model reads the description and asks for the tool when it needs it.

🔁

An agent is the loop

The model picks a tool, your code runs it, the result goes back to the model, and it repeats until the task is done. That loop is what turns a chatbot into something that gets work done.

Why agents now?

  • Models got good at tool calling. Modern models, including open ones you can run in Ollama, can reliably return a structured "call this function with these arguments" request.
  • Frameworks standardised the loop. LangChain handles the plumbing, so you write plain Python functions instead of parsing model output by hand.
  • Real tasks need several steps. "Weather in Delhi and 23 * 7 + 4" needs two different lookups. One prompt can't do that, but a loop with tools can.
Remember: the model is the brain, the tools are the hands. A bigger model picks tools more reliably, and every tool you give it is something it can actually do, so only hand over what you're comfortable with.

What is an agent?

An agent is an LLM, plus tools, running in a loop.

User question
→
LLMdecides what to do
→
Tool callyour Python function
→
Resultfed back to LLM
↺
Final answer
Key idea: the model never runs your code. It returns a structured request ("call get_weather with city='Delhi'"). The framework runs the function and hands the result back.
1

Install

bash
pip install -U langchain langchain-ollama langchain-google-genai

Pull a model that supports tool calling (not every model does). llama3.1 and qwen3 do; check the tools tag on the Ollama library.

bash
ollama pull llama3.1:8B
2

Turn Python functions into tools

The @tool decorator uses the function name, type hints and docstring to tell the model what the tool does. A good docstring is a good prompt.

python · tools.py
from langchain.tools import tool

@tool
def get_weather(city: str) -> str:
    """Get the current weather for a city."""
    # Demo data. Replace with a real weather API call.
    fake = {"delhi": "34°C, hazy", "london": "14°C, rain", "tokyo": "22°C, clear"}
    return fake.get(city.lower(), "no data for that city")

@tool
def calculate(expression: str) -> str:
    """Evaluate a basic math expression like '23 * 7 + 4'."""
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        return "Only numbers and + - * / ( ) are allowed."
    return str(eval(expression))
Careful with eval. The character allow-list above is fine for a demo, but never eval raw model output in real code. Use a proper math parser instead.
3

Build the agent (local model)

create_agent wires the model, tools and the loop together.

python · agent_local.py
from langchain.agents import create_agent
from langchain_ollama import ChatOllama
from tools import get_weather, calculate

model = ChatOllama(model="llama3.1:8B", temperature=0)

agent = create_agent(
    model,
    tools=[get_weather, calculate],
    system_prompt="You are a helpful assistant. Use tools when they help.",
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "What's the weather in Delhi, and what is 23 * 7 + 4?"}]
})

# Print the whole trace: user → tool call → tool result → answer
for m in result["messages"]:
    m.pretty_print()

The trace is the best part of the demo: pause on the AI message with tool calls, then the Tool message, then the final answer.

4

Swap in the cloud model: one line changes

Tools and agent stay identical. Only the model object changes. That's the payoff of using a framework.

python · agent_cloud.py
from langchain_google_genai import ChatGoogleGenerativeAI

# reads GOOGLE_API_KEY from the environment
model = ChatGoogleGenerativeAI(model="gemini-3.5-flash", temperature=0)

agent = create_agent(model, tools=[get_weather, calculate])
Heads-up: langchain-google-genai reads GOOGLE_API_KEY (or you can pass google_api_key=...). If your key is in GEMINI_API_KEY, export it under that name too: export GOOGLE_API_KEY=$GEMINI_API_KEY.
5

Stream the steps live

python
for step in agent.stream(
    {"messages": [{"role": "user", "content": "Compare the weather in London and Tokyo."}]},
    stream_mode="values",
):
    step["messages"][-1].pretty_print()
